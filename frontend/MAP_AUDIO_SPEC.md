# 📣 Голосовые сообщения на карте (Telegram WebApp)

Документ описывает реализацию функции записи и доставки кратких аудио‑сообщений для всех активных участников на карте.

## 🎯 Цели
- Позволить участнику записать аудио (5–15 сек) и «озвучить» его для всех, кто сейчас на карте.
- Обеспечить простой и надёжный UX без веб‑сокетов (hostland/PHP), на базе краткого опроса (polling).
- Соблюдать политики браузеров по autoplay: проигрывать автоматически только после явного разрешения пользователя.

---

## 🧭 Пользовательские сценарии (UX)
1) «REC» (кнопка посередине внизу)
   - Удержание → старт записи (появляется оверлей с прогрессом и кнопкой «отмена»/«отправить»).
   - Отпустил → запись останавливается (если ≥1 сек), предлагается «Отправить»/«Отмена».
   - Ошибки (нет микрофона/разрешения) → верхняя плашка ошибок.

2) Получение новых аудио
   - Внизу карты (на панель/рядом с FAB) всплывает компактный баннер «Новое аудио от Имя (@user) — ▶️» или мини‑кружок‑плеер над маркером автора.
   - При включённом тогле «Голосовые оповещения» и после первого пользовательского жеста — можно играть автоматически.

3) Мини‑плеер
   - Круглая кнопка с прогрессом (как на наших FAB), play/pause, оставшееся время.
   - Отключаем одновременное проигрывание нескольких сообщений.

---

## 🧩 Компоненты UI (Frontend)
- FAB «REC» (уже в интерфейсе, пока показывает «в разработке»):
  - Состояния: idle / recording / sending / error.
  - Индикатор записи (мигающий), таймер, ограничение на длительность.
- Тогл «Голосовые оповещения» (в настройках карты или шестерёнка рядом с FAB):
  - Включает/выключает автоматическое проигрывание новых сообщений.
- Мини‑плеер над маркерами и/или в нижней панели:
  - State: new/unread, playing, paused, finished.
- Верхняя плашка ошибок (есть в карте).

## 🔌 Реализация на фронтенде
- Запись: `MediaRecorder` (контейнер webm/ogg), моно 16 kHz достаточно.
  - iOS: возможна ограниченная поддержка; если `MediaRecorder` недоступен — честное сообщение пользователю.
- Ограничения:
  - Длительность: `MAP_AUDIO_MAX_DURATION_SEC` (по умолчанию 15 сек).
  - Размер: `MAP_AUDIO_MAX_SIZE_MB` (по умолчанию 2–3 MB).
- Отправка:
  - `POST /api/map-audio` (multipart/form-data): поля `audio` (blob), `latitude`, `longitude`, `duration_sec`.
  - Заголовки авторизации: X‑Telegram‑* (как во всех запросах WebApp).
- Доставка (без WebSocket):
  - `GET /api/map-audio?since=timestamp` — отдаёт список новых сообщений.
  - Периоды опроса: в покое `MAP_AUDIO_POLL_IDLE_SEC` (30–60 сек), в движении `MAP_AUDIO_POLL_MOVING_SEC` (10–20 сек).
- Автопроигрывание:
  - По политикам браузеров нужен пользовательский жест. Пользователь включает «Голосовые оповещения» — считаем разрешением, и запускаем `audio.play()` в том же жесте (обход лимитов autoplay).
  - Если autoplay заблокирован — показываем баннер «Новая запись ▶️».
- Кэширование:
  - Локальный кэш полученных метаданных (id, url, expires_at) на время сессии.
  - Неигранные помечаем значком на карте/в списке.

## 🗄️ Backend (PHP, routes)

### Таблица `map_audio_messages`
- id (PK, BIGINT)
- user_id (FK → users.id)
- file_url (VARCHAR) — путь в `uploads/audio/..`
- mime (VARCHAR 64) — `audio/webm`, `audio/ogg`, `audio/m4a`
- duration_sec (INT)
- latitude (DECIMAL(9,6))
- longitude (DECIMAL(9,6))
- created_at (TIMESTAMP)
- expires_at (TIMESTAMP) — TTL (например, +15 мин или = `map_live_time_min`)

Индексы:
- INDEX `created_at`
- INDEX `(expires_at)` (для очистки)
- INDEX `(latitude, longitude)` опционально для геофильтра, если понадобится

### Эндпоинты
1) `POST /api/map-audio`
   - Auth: Telegram headers (минимальная роль: member).
   - Валидация: MIME/размер/длительность.
   - Сохранение файла `uploads/audio/..`, запись в БД, вычисление `expires_at`.
   - Ответ: `{ success:true, data:{ id, file_url, mime, duration_sec, user:{id,first_name,username,photo.mini}, created_at, expires_at } }`

2) `GET /api/map-audio?since=ISO8601`
   - Auth: Telegram headers.
   - Возвращает список сообщений, созданных после `since` и не просроченных (`expires_at > NOW()`), отсортированных по `created_at`.
   - Можно добавить фильтры: `within_km`, bbox (если нужно ограничить объём).

### Безопасность
- Принимать только допустимые MIME (белый список).
- Лимиты: rate limit (например, не чаще 1 запись/30 сек на пользователя), анти‑флуд.
- Очистка просроченных файлов/записей cron‑утилитой (скрипт в `backend/utils/cleanup_audio.php`).
- Доступ централизованно: добавить роли в `config/sectionGroups.php` (минимум `member`).

---

## 🔐 Валидация/обработка файлов
- Сервер: проверка заголовка файла (`finfo`), размер ≤ `MAP_AUDIO_MAX_SIZE_MB`.
- Генерация уникального имени: `audio_{userId}_{timestamp}.webm`.
- Хранение только локально (без внешних CDN) → быстрый и стабильный доступ.

---

## ⚙️ Переменные окружения (.env)
- `MAP_AUDIO_TTL_MIN=15` — время жизни аудио на карте.
- `MAP_AUDIO_MAX_DURATION_SEC=15`
- `MAP_AUDIO_MAX_SIZE_MB=3`
- `MAP_AUDIO_POLL_IDLE_SEC=60`
- `MAP_AUDIO_POLL_MOVING_SEC=20`

При необходимости: `UPLOADS_BASE_URL` уже используется для ссылок.

---

## 🚦 Ограничения и поведение
- Автовоспроизведение возможно только после пользовательского жеста (политики браузера). Включение тогла «Голосовые оповещения» = жест.
- iOS: если `MediaRecorder` недоступен — отображаем подсказку, что запись не поддерживается, без деградации остального функционала.
- Сообщения не храним вечно — автоочистка по TTL.

## 🧪 Тестирование
- Запись/отправка на Android Chrome / iOS Safari.
- Размер и длительность превышения — сервер отвечает 400 и понятной ошибкой.
- Пуллинг — проверка на idle/moving интервалы.
- Автопроигрывание: после включения тогла должно работать (если браузер не блокирует звук системой), иначе — баннер с Play.
