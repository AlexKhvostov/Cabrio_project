# 🧪 Интеграционные тесты backend

## 📋 Быстрое создание тестов

### 🚀 Автоматическое создание
1. Откройте: `http://localhost:8000/_tests/create_test.php`
2. Заполните форму
3. Скопируйте сгенерированный код
4. Создайте файл `{id}_test.php`
5. Добавьте тест в `tests_config.json`

### 📝 Ручное создание из шаблона
1. Скопируйте `test_template.php`
2. Измените конфигурацию в начале файла:
```php
$test_config = [
    'id' => 'your_test_name',           // ID теста
    'name' => 'Название теста',         // Отображаемое название
    'description' => 'Описание',        // Что тестирует
    'endpoint' => '/api/endpoint',      // API endpoint
    'method' => 'GET',                  // HTTP метод
    'icon' => '🔧',                     // Иконка
    'data_name' => 'записей'           // Название данных
];
```

## 📊 Структура тестов

### 📁 Файлы
- `index.php` — главная таблица всех тестов
- `create_test.php` — генератор новых тестов
- `test_template.php` — шаблон для тестов
- `tests_config.json` — конфигурация тестов
- `{name}_test.php` — отдельные тестовые файлы

### 🎯 Что тестирует каждый файл
- `users_list_test.php` — GET /api/users
- `cars_list_test.php` — GET /api/cars  
- `events_list_test.php` — GET /api/events
- `guide_objects_list_test.php` — GET /api/guide-objects

## 🔧 Добавление нового теста

### 1. Создание тестового файла
```bash
# Скопируйте шаблон
cp test_template.php new_test_test.php

# Или используйте генератор
# http://localhost:8000/_tests/create_test.php
```

### 2. Настройка конфигурации
Измените параметры в начале файла:
```php
$test_config = [
    'id' => 'new_test',
    'name' => 'Новый тест',
    'description' => 'Описание теста',
    'endpoint' => '/api/new-endpoint',
    'method' => 'GET',
    'icon' => '🔧',
    'data_name' => 'записей'
];
```

### 3. Добавление в tests_config.json
```json
{
  "id": "new_test",
  "name": "Новый тест",
  "description": "Описание теста",
  "endpoint": "/api/new-endpoint",
  "method": "GET",
  "expected": {
    "success": true,
    "has_data": true,
    "data_type": "array"
  },
  "icon": "🔧",
  "category": "new_category"
}
```

## 🎨 Особенности тестов

### ✅ Что показывают тесты
- **Запрос** — метод, URL, заголовки
- **Ответ** — статус, тело ответа
- **Результат** — успех/ошибка, количество записей
- **Пример данных** — структура ответа для отладки
- **Время выполнения** — скорость работы API

### 🔗 Навигация
- **Главная таблица** — общий обзор всех тестов
- **Детальные страницы** — полная информация для отладки
- **Ссылка "Назад"** — возврат к таблице
- **Ссылка "Создать тест"** — генератор новых тестов

## 🚀 Запуск тестов

# 🤖 ИНСТРУКЦИЯ ДЛЯ AI: Как добавлять новые тесты

## 📋 Пошаговый алгоритм для AI

### **Шаг 1: Определение нового теста**
```markdown
1. Понять какой API endpoint нужно протестировать
2. Определить HTTP метод (GET, POST, PUT, DELETE)
3. Выяснить ожидаемую структуру ответа
4. Выбрать подходящую иконку и название данных
```

### **Шаг 2: Создание тестового файла**
```bash
# Всегда используйте шаблон test_template.php
# НЕ создавайте файлы с нуля!
```

**Пример для AI:**
```php
// Копируем шаблон и настраиваем конфигурацию
$test_config = [
    'id' => 'users_create',              // Уникальный ID без пробелов
    'name' => 'Создание пользователя',   // Человекочитаемое название
    'description' => 'POST запрос для создания нового пользователя с фото',
    'endpoint' => '/api/users',          // Точный API endpoint
    'method' => 'POST',                  // HTTP метод
    'icon' => '👤',                     // Эмодзи иконка
    'data_name' => 'пользователей'      // Название в родительном падеже
];
```

### **Шаг 3: Добавление в tests_config.json**
```json
{
  "id": "users_create",
  "name": "Создание пользователя", 
  "description": "POST запрос для создания нового пользователя с фото",
  "endpoint": "/api/users",
  "method": "POST",
  "expected": {
    "success": true,
    "has_data": true,
    "data_type": "object"
  },
  "icon": "👤",
  "category": "users"
}
```

### **Шаг 4: Проверка совместимости**
```markdown
✅ Проверить что файл {id}_test.php создан
✅ Проверить что тест добавлен в tests_config.json  
✅ Проверить что endpoint существует в backend
✅ Проверить что метод поддерживается
✅ Проверить что иконка отображается корректно
```

## 🔧 Технические требования для AI

### **Обязательные поля в конфигурации:**
- `id` — уникальный идентификатор (без пробелов, латиница)
- `name` — отображаемое название на русском
- `description` — подробное описание что тестирует
- `endpoint` — точный API endpoint (начинается с /api/)
- `method` — HTTP метод (GET, POST, PUT, DELETE)
- `icon` — эмодзи иконка
- `data_name` — название данных в родительном падеже

### **Правила именования:**
```markdown
ID теста: {сущность}_{действие} (users_list, cars_create, events_update)
Название: "Действие сущности" (Список пользователей, Создание автомобиля)
Endpoint: /api/{сущность} или /api/{сущность}/{id}
Иконка: подходящий эмодзи (👤, 🚗, 📅, 🗺️, 💳)
```

### **Ожидаемые результаты:**
```json
{
  "success": true,           // API вернул успех
  "has_data": true,          // Есть данные в ответе
  "data_type": "array"       // Тип данных (array/object)
}
```

## 🚨 Частые ошибки для AI

### **❌ НЕ делайте:**
- Создавать файлы без использования шаблона
- Использовать пробелы в ID теста
- Забывать добавлять тест в tests_config.json
- Использовать неправильные HTTP методы
- Неправильно указывать endpoint

### **✅ Всегда делайте:**
- Используйте test_template.php как основу
- Проверяйте что endpoint существует в backend
- Тестируйте тест после создания
- Добавляйте понятные описания
- Используйте подходящие иконки
