# 🏗️ Обзор архитектуры бэкенда CabrioRide

> **Назначение:** Принципы и структура архитектуры бэкенда  
> **Версия:** 1.0.0  
> **Последнее обновление:** 2024-01-01

---

## 🎯 **Принципы архитектуры**

### **1. Разделение ответственности**
- Каждый компонент имеет чёткую зону ответственности
- Минимальные зависимости между компонентами
- Чистые интерфейсы между слоями

### **2. Уровни абстракции (L0-L4)**
```
L4 (Комплексные) → L3 (Сложные) → L2 (Бизнес) → L1 (Базовые) → L0 (Модели)
```

### **3. Централизованная авторизация**
- Единая точка авторизации через AuthMiddleware
- Ролевая модель доступа
- Централизованная конфигурация прав

### **4. Бизнес-логика в Actions**
- Actions как единицы бизнес-логики
- Переиспользование и комбинирование
- Чёткая иерархия вызовов

---

## 🏛️ **Структура системы**

### **Основные компоненты**

#### **1. Контроллеры (HTTP-слой)**
- **Назначение:** Обработка HTTP-запросов
- **Расположение:** `controllers/`
- **Примеры:** `UserController.php`, `CarController.php`

#### **2. Actions (бизнес-логика)**
- **Назначение:** Реализация бизнес-логики
- **Расположение:** `actions/level1/`, `actions/level2/`, `actions/level3/`
- **Примеры:** `__SyncUserDataAction.php`, `___CheckCarInClubAction.php`

#### **3. Модели (работа с БД)**
- **Назначение:** CRUD операции с базой данных
- **Расположение:** `models/`
- **Примеры:** `User.php`, `Car.php`, `Event.php`

#### **4. Утилиты (вспомогательные классы)**
- **Назначение:** Общие функции и хелперы
- **Расположение:** `utils/`
- **Примеры:** `AuthHelper.php`, `SessionHelper.php`, `AppContext.php`

#### **5. Middleware (промежуточные слои)**
- **Назначение:** Авторизация и валидация
- **Расположение:** `middleware/`
- **Примеры:** `AuthMiddleware.php`

---

## 🔄 **Поток запроса**

### **Стандартный поток**
```
HTTP Request → Router → AuthMiddleware → Controller → Action → Model → Database
                ↓              ↓              ↓
              Utils ←────── Utils ←────── Utils
                ↓              ↓              ↓
           External APIs   File System   Logging
```

### **Детальный поток**

1. **HTTP Request** — запрос приходит на сервер
2. **Router** (`routes/api.php`) — маршрутизация запроса
3. **AuthMiddleware** — проверка авторизации и прав доступа
4. **Controller** — обработка HTTP-слоя
5. **Action** — выполнение бизнес-логики
6. **Model** — работа с базой данных
7. **Response** — формирование ответа

## 🎯 **Уровни абстракции**

### **L0 (Модели) — работа с БД**
- **Назначение:** Прямые CRUD операции
- **Префикс:** Без префикса
- **Примеры:** `User.php`, `Car.php`
- **Ограничения:** Только работа с БД, без бизнес-логики

### **L1 (Базовые операции) — простые комбинации**
- **Назначение:** Комбинация 2-3 операций L0
- **Префикс:** `_` (одно подчёркивание)
- **Примеры:** `_CreateUserAction.php`, `_UpdateStatusAction.php`
- **Ограничения:** Простая бизнес-логика

### **L2 (Бизнес-операции) — проверки и правила**
- **Назначение:** Используют L1 Actions, добавляют бизнес-правила
- **Префикс:** `__` (два подчёркивания)
- **Примеры:** `__SyncUserDataAction.php`, `__SearchCarAction.php`
- **Ограничения:** Проверки прав доступа, валидация

### **L3 (Сложные сценарии) — транзакции и интеграции**
- **Назначение:** Используют L2 Actions, транзакции, внешние API
- **Префикс:** `___` (три подчёркивания)
- **Примеры:** `___CheckCarInClubAction.php`, `___LeaveBusinessCardAction.php`
- **Ограничения:** OCR интеграция, сложные транзакции

### **L4 (Комплексные сценарии) — полные пользовательские сценарии**
- **Назначение:** Используют L3 Actions, полные сценарии
- **Префикс:** `____` (четыре подчёркивания)
- **Примеры:** `____ExecuteUserOnboardingAction.php`
- **Ограничения:** Оркестрация множественных операций

## 🔄 **Взаимодействие компонентов**

### **Правила вызовов**
- **L4** может вызывать **L3, L2, L1** Actions
- **L3** может вызывать **L2, L1** Actions  
- **L2** может вызывать **L1** Actions
- **L1** может вызывать только **L0** Models
- **L0** (Models) не вызывает Actions

### **Передача данных**
- **Стандартный формат** входных/выходных данных
- **Валидация** на каждом уровне
- **Обработка ошибок** единообразно
- **Логирование** всех операций
