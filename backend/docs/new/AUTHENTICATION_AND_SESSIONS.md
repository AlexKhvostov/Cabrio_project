# 🔐 Система авторизации и сессий CabrioRide

## 📋 Обзор архитектуры

CabrioRide использует **централизованную систему авторизации** на основе Telegram данных. Вся логика авторизации и управления сессиями сосредоточена на бэкенде, что обеспечивает безопасность и единообразие работы.

### 🎯 Основные принципы

1. **Единая точка входа** — все запросы проходят через единую систему авторизации
2. **Telegram-центричность** — вся авторизация основана на Telegram ID пользователя
3. **Сессионная модель** — пользователь получает сессию после успешной авторизации
4. **Автоматическая синхронизация** — данные пользователя автоматически синхронизируются при каждом запросе

## 🚀 Процесс работы с эндпоинтами

### 1️⃣ Получение запроса

**Где:** `backend/routes/api.php` (точка входа)

**Что происходит:**
- Запрос приходит на любой API эндпоинт
- Роутер определяет маршрут и метод
- **ВАЖНО:** Все запросы проходят через единую систему авторизации

### 2️⃣ Извлечение Telegram данных

**Где:** `backend/utils/AuthHelper.php` → `extractTelegramData()`

**Что происходит:**
- Извлекаются Telegram данные из запроса (заголовки, тело запроса, параметры)
- Проверяется наличие обязательного поля: `telegram_id`
- Остальные поля (`first_name`, `last_name`, `username`, `photo_url`) — опциональные
- Валидируется формат данных через `ValidationHelper`

**Поддерживаемые источники данных:**
- HTTP заголовки (`X-Telegram-ID`, `X-Telegram-First-Name`, и т.д.)
- JSON тело запроса
- FormData поля
- GET параметры (для тестирования)

### 3️⃣ Проверка/создание пользователя

**Где:** `backend/utils/AuthHelper.php` → `ensureUserExists()`

**Что происходит:**
- Вызывается `__SyncUserDataAction` для синхронизации пользователя
- Если пользователь не существует — создается с ролью `guest`
- Если существует — обновляются данные при необходимости
- Возвращается полная информация о пользователе

### 4️⃣ Создание/обновление сессии

**Где:** `backend/utils/SessionHelper.php` → `createOrUpdateSession()`

**Что происходит:**
- Генерируется уникальный `session_id`
- Создается запись в таблице `sessions` с привязкой к `user_id`
- Устанавливается время жизни сессии (1 час для безопасности)
- Сессия связывается с текущим запросом
- **Для Telegram Bot:** сессия создается временно, бот не сохраняет session_id

### 5️⃣ Проверка прав доступа

**Где:** `backend/utils/AuthHelper.php` → `checkAccess()`

**Что происходит:**
- Определяется требуемая роль для эндпоинта из `config/sectionGroups.php`
- Проверяется роль пользователя в сессии
- Если прав недостаточно — возвращается ошибка 403
- Если все в порядке — запрос передается дальше

### 6️⃣ Выполнение бизнес-логики

**Где:** Соответствующий контроллер → Action

**Что происходит:**
- Контроллер получает запрос с уже авторизованным пользователем
- Вызывается соответствующий Action (L2 или L3)
- Action работает с данными пользователя из сессии
- Возвращается результат

## 🔧 Техническая реализация

### Middleware система

**Файл:** `backend/middleware/AuthMiddleware.php`

**Назначение:** Централизованная обработка авторизации

**Логика работы:**
1. Перехватывает все запросы к API
2. Извлекает Telegram данные
3. Синхронизирует пользователя
4. Создает/обновляет сессию
5. Проверяет права доступа
6. Передает управление контроллеру

### Хелперы и их роли

#### `AuthHelper.php`
- **`extractTelegramData()`** — извлечение Telegram данных из запроса
- **`ensureUserExists()`** — гарантированное существование пользователя
- **`checkAccess()`** — проверка прав доступа
- **`getCurrentUser()`** — получение текущего пользователя из сессии

#### `SessionHelper.php`
- **`createOrUpdateSession()`** — создание/обновление сессии
- **`validateSession()`** — проверка валидности сессии
- **`getSessionUser()`** — получение пользователя по сессии
- **`destroySession()`** — уничтожение сессии

#### `ValidationHelper.php`
- **`validateTelegramData()`** — валидация Telegram данных
- **`requireTelegramFields()`** — проверка обязательных полей

### Интеграция с роутером

**Файл:** `backend/routes/api.php`

**Логика:**
```php
// 1. Подключаем middleware
require_once __DIR__ . '/../middleware/AuthMiddleware.php';

// 2. Обрабатываем авторизацию для всех запросов
$authResult = AuthMiddleware::process();

// 3. Если авторизация не прошла — возвращаем ошибку
if (!$authResult['success']) {
    echo ResponseHelper::authError($authResult['message']);
    exit;
}

// 4. Передаем управление контроллеру с авторизованным пользователем
$controller = new $controllerClass();
$controller->setCurrentUser($authResult['user']);
$controller->$method();
```

## 📊 Схема работы с сессиями

### Создание сессии
1. Пользователь отправляет Telegram данные
2. Система проверяет/создает пользователя
3. Генерируется уникальный `session_id`
4. Создается запись в БД: `sessions` (id, user_id, session_id, created_at, expires_at)
5. `session_id` возвращается в ответе

### Использование сессии
1. Клиент отправляет `session_id` в заголовке `X-Session-ID`
2. Система проверяет валидность сессии
3. Извлекает пользователя по `user_id` из сессии
4. Проверяет права доступа
5. Выполняет запрос

### Обновление сессии
- При каждом запросе время жизни сессии продлевается
- Если сессия истекла — создается новая
- Старые сессии автоматически очищаются

## 🔒 Безопасность

### Валидация данных
- Все Telegram данные проходят строгую валидацию
- Проверяется формат `telegram_id` (число)
- Валидируются имена пользователя
- Проверяется уникальность Telegram ID

### Защита сессий
- `session_id` генерируется криптографически стойко
- Сессии имеют ограниченное время жизни
- Автоматическая очистка истекших сессий
- Защита от перехвата через HTTPS

### Права доступа
- Централизованная система ролей
- Проверка прав на уровне middleware
- Логирование всех попыток доступа
- Возможность блокировки пользователей

## 🔄 Интеграция с Telegram Bot

### WebApp интеграция
1. Telegram WebApp передает данные пользователя в заголовках
2. Бэкенд автоматически извлекает эти данные
3. Создается сессия для WebApp пользователя
4. Все последующие запросы используют эту сессию

### Bot интеграция
1. Bot отправляет данные пользователя в каждом запросе
2. Система синхронизирует пользователя
3. Создается временная сессия для бота (1 час)
4. Bot получает результат, но НЕ сохраняет `session_id`
5. При следующем запросе бот снова отправляет Telegram данные

## 🛠️ Конфигурация

### Настройки сессий
```php
// config/session.php
return [
    'lifetime' => 3600, // 1 час (для безопасности)
    'cleanup_interval' => 1800, // очистка каждые 30 минут
    'max_sessions_per_user' => 3,
    'secure_cookies' => true,
];
```

### Настройки авторизации
```php
// config/auth.php
return [
    'required_telegram_fields' => ['telegram_id'],
    'optional_telegram_fields' => ['first_name', 'last_name', 'username', 'photo_url'],
    'default_role' => 'guest',
    'session_timeout' => 3600, // 1 час
];
```
