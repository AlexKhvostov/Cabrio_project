# 🚗 MVP Management Endpoints

## 📋 Обзор ключевых функций MVP

Система CabrioRide поддерживает 4 критически важные функции для MVP:

1. **👤 Создание/обновление пользователя** - регистрация и синхронизация пользователя
   - **L3 Action:** `___SyncUserFromTelegramAction`
2. **🔍 Проверка авто** - узнать есть ли авто в базе клуба
   - **L3 Action:** `___CheckCarInClubAction`
3. **🏷️ Оставление визитки** - оставить визитку в авто
   - **L3 Action:** `___LeaveBusinessCardAction`
4. **🚙 Добавление в гараж** - добавить авто в свой гараж
   - **L3 Action:** `___AddCarToGarageAction`

**Эти функции составляют основу MVP и покрывают все основные сценарии работы с пользователями и автомобилями.**

---

## 👤 Функция 1: Создание/обновление пользователя

### Endpoint
```
POST /api/users/sync-from-telegram
```

### L3 Action
```
___SyncUserFromTelegramAction
```

### Описание
**Критически важная функция MVP:** Пользователь обращается к системе через Telegram, нужно создать или обновить его профиль в базе данных.

### Логика обработки
1. **Проверка существования пользователя** (`_CheckUserByTelegramIdAction`)
   - Если пользователь найден → обновление данных (`_UpdateUserAction`)
   - Если пользователь не найден → создание нового (`_CreateUserAction`)
2. **Создание пользователя** (если не найден)
   - Роль по умолчанию: `guest` (устанавливается в `_CreateUserAction`)
3. **Обновление пользователя** (если найден)
   - Обновление только изменившихся полей
   - Сохранение существующей роли

### Входные данные
```json
{
  "telegram_id": 123456789,
  "first_name": "Иван",
  "last_name": "Иванов",
  "username": "ivan_ivanov",
  "language_code": "ru"
}
```

### Возможные ответы

**✅ Пользователь создан:**
```json
{
  "success": true,
  "data": {
    "user_id": 15,
    "action": "created",
    "role": "guest",
    "status": "active",
    "message": "Пользователь успешно создан"
  }
}
```

**✅ Пользователь обновлен:**
```json
{
  "success": true,
  "data": {
    "user_id": 15,
    "action": "updated",
    "role": "member",
    "status": "active",
    "updated_fields": ["first_name", "username"],
    "message": "Данные пользователя обновлены"
  }
}
```

**✅ Пользователь найден без изменений:**
```json
{
  "success": true,
  "data": {
    "user_id": 15,
    "action": "no_changes",
    "role": "member",
    "status": "active",
    "message": "Данные пользователя актуальны"
  }
}
```

## 🚗 Функция 2: Проверка авто

### Endpoint
```
POST /api/cars/check-in-club
```

### L3 Action
```
___CheckCarInClubAction
```

### Описание
**Ключевая функция MVP:** Пользователь загружает фото авто и хочет узнать есть ли оно в базе клуба.

### Логика обработки
1. **Распознавание номера** (`RecognizeCarNumberFromPhotoAction`)
   - Если не распознался → ошибка и выход
2. **Проверка существования авто** (`__SearchCarAction`)
      Проверка существования авто (`_CheckCarInDbAction`)
      Бизнес-логика : 
          - **Если авто есть** → 
                Возврат: номер, статус, "есть в клубе"
          - **Если авто нет** → 
              Создание авто (`_CreateCarAction`)
              Установить ей статус "замечена" (`_UpdateStatusAction`)
                Возврат: номер, "нет в клубе"

### Входные данные
```json
{
  "photo": "file",
  "telegram_id": 123456789
}
```

### Возможные ответы

**✅ Авто найдено:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "status": "Активный",
    "message": "Автомобиль найден в базе клуба"
  }
}
```

**✅ Авто создано:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "status": "Замечена",
    "message": "Автомобиль не в клубе. Добавлен в базу"
  }
}
```

**❌ Ошибка распознавания:**
```json
{
  "success": false,
  "error": {
    "code": "PLATE_NOT_RECOGNIZED",
    "message": "Не удалось распознать номер автомобиля"
  }
}
```

## 🏷️ Функция 3: Оставление визитки

### Endpoint
```
POST /api/cars/leave-business-card
```

### L3 Action
```
___LeaveBusinessCardAction
```

### Описание
**Ключевая функция MVP:** Пользователь загружает фото авто и хочет оставить визитку в этом авто.

### Логика обработки
1. **Распознавание номера** (`RecognizeCarNumberFromPhotoAction`)
   - Если не распознался → ошибка и выход
2. **Оставляем визитку** (`__DropBusinessCardAction`)
      Проверка существования авто (`_CheckCarInDbAction`)
      Бизнес-логика: 
        - **Если авто есть:**
          - Статус "замечена" → обновить на "визитка" ("`_UpdateStatusAction`")
          - Статус "активный" или "визитка" → не изменять 
        - **Если авто нет** → 
            - Создать авто (`_CreateCarAction`)
            - Установить статусом "визитка" (`_UpdateStatusAction`)
            - Создать визитку (`_CreateBusinessCardAction`)
      **Сохранить фото к визитке** (`_CreatePhotoAction`)

### Входные данные
```json
{
  "photo": "file",
  "telegram_id": 123456789,
  "message": "Текст визитки (опционально)"
}
```

### Возможные ответы

**✅ Визитка оставлена:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "car_status": "Визитка",
    "business_card_id": 15,
    "message": "Визитка успешно оставлена в автомобиле"
  }
}
```

**✅ Статус не изменен:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "car_status": "Активный",
    "business_card_id": 16,
    "message": "Визитка оставлена, статус авто не изменен"
  }
}
```

## 🚙 Функция 4: Добавление авто в гараж

### Endpoint
```
POST /api/cars/add-to-garage
```

### L3 Action
```
___AddCarToGarageAction
```

### Описание
**Ключевая функция MVP:** Пользователь загружает фото авто и хочет добавить его в свой "гараж".

### Логика обработки
1. **Распознавание номера** (`RecognizeCarNumberFromPhotoAction`)
   - Если не распознался → ошибка и выход
2 **Добавление авто пользователю** (`__AddCarToUserAction`)
        Проверка существования авто (`_CheckCarInDbAction`)
        Бизнес-логика:
        - **Если авто есть:**
          - Другой владелец → ошибка "уже есть владелец"
          - Наш владелец → обновить статус на "активный", добавить фото (`_UpdateStatusAction`)
          - Нет владельца → установить владельцем, статус "активный" (`_UpdateStatusAction`)
        - **Если авто нет** → 
          - Создать авто  (`_CreateCarAction`)
          - установить статус "активный" (`_UpdateStatusAction`)
          - установить владелец = пользователь (`_UpdateOwnerToCarAction`)

### Входные данные
```json
{
  "photo": "file",
  "telegram_id": 123456789
}
```

### Возможные ответы

**✅ Авто добавлено в гараж:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "car_status": "Активный",
    "owner_status": "Установлен владелец",
    "message": "Автомобиль успешно добавлен в ваш гараж"
  }
}
```

**✅ Уже ваш владелец:**
```json
{
  "success": true,
  "data": {
    "plate_number": "A123BC",
    "car_status": "Активный",
    "owner_status": "Уже владелец",
    "message": "Вы уже являетесь владельцем этого автомобиля"
  }
}
```

**❌ Уже есть владелец:**
```json
{
  "success": false,
  "error": {
    "code": "CAR_HAS_OTHER_OWNER",
    "message": "У этого автомобиля уже есть владелец",
    "data": {
      "current_owner_id": 5
    }
  }
}
```

## 🎯 MVP Приоритеты

### ✅ **Критически важные функции:**
1. **Проверка авто** - основа взаимодействия с системой
2. **Оставление визиток** - социальная функция клуба
3. **Управление гаражом** - личная коллекция пользователя

### ✅ **Покрытие пользовательских сценариев:**
- **Новый пользователь** → проверка авто → добавление в гараж
- **Активный пользователь** → оставление визиток → взаимодействие с сообществом
- **Владелец авто** → управление своим гаражом

### ✅ **Техническая готовность:**
- Все необходимые Actions созданы
- API endpoints настроены
- База данных готова
- OCR интеграция работает

## 🔧 Технические детали

### Используемые Actions

#### utils (Внешние интеграции)
- `RecognizeCarNumberFromPhotoAction` - распознавание номера авто

#### L1 (Базовые операции)
- `_CheckUserByTelegramIdAction` - Проверка существования пользователя по Telegram ID
- `_CreateUserAction` - Создание пользователя
- `_UpdateUserAction` - Обновление данных пользователя
- `_CheckCarInDbAction` - Проверка существования авто в базе 
- `_UpdateStatusAction` - Изменение статуса сущности 
- `_UpdateRoleUserAction` - Изменение роли пользователя 
- `_UpdateOwnerToCarAction` - Установить владельца авто 
- `_CreateCarAction` - Создание авто
- `_CreateBusinessCardAction` - Создание визитки
- `_CreatePhotoAction` - Создание фото (если есть фото)



#### L2 (Бизнес-операции)

- `__SyncUserDataAction` - Синхронизация данных пользователя (проверка существования, создание или обновление)
- `__AddCarToUserAction` - Добавление авто пользователю (если авто был в БД и без владельца то ставит владельца (`_UpdateOwnerToCarAction`), если нет в БД то создает (`_CreateCarAction`))
- `__DropBusinessCardAction` - Добавление визитки в базу с проверкой существования авто (`_CheckCarInDbAction`), и созданием авто если её нет (`_CreateCarAction`) с статусом визитка (`_UpdateStatusAction`)
- `__SearchCarAction` - Поиск авто в базе (`_CheckCarInDbAction`), и созданием авто если её нет (`_CreateCarAction`) с статусом "замечена" (`_UpdateStatusAction`)



#### L3 (Сложные сценарии)
- `___SyncUserFromTelegramAction` - Полный сценарий синхронизации пользователя из Telegram
- `___CheckCarInClubAction` - Полный сценарий проверки авто в клубе
- `___LeaveBusinessCardAction` - Полный сценарий оставления визитки
- `___AddCarToGarageAction` - Полный сценарий добавления в гараж

### Статусы автомобилей
- **Замечен** (ID=1, code=noticed) - автомобиль замечен ботом по фото
- **Визитка** (ID=2, code=business_card) - автомобиль с оставленной визиткой
- **Активный** (ID=7, code=active) - активный автомобиль участника

### Авторизация
Все эндпоинты требуют `telegram_id` для авторизации пользователя.

### Обработка ошибок
- Распознавание номера не удалось
- Автомобиль уже имеет другого владельца
- Ошибки создания записей в БД
- Ошибки загрузки файлов
