# 🏗️ Архитектура и последовательность выполнения CabrioRide

## 📋 Общая архитектура

CabrioRide построен по принципу **слоистой архитектуры** с четким разделением ответственности:

```
┌─────────────────────────────────────────────────────────────┐
│                    Frontend (Vue.js)                       │
│              (только отображение данных)                   │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    API Gateway                             │
│              (backend/routes/api.php)                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                AuthMiddleware                              │
│           (авторизация и сессии)                          │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  Controllers                               │
│           (маршрутизация запросов)                        │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    Actions                                 │
│           (бизнес-логика L1/L2/L3)                       │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    Models                                  │
│              (работа с базой данных)                      │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  Database (MySQL)                          │
└─────────────────────────────────────────────────────────────┘
```

## 🔄 Последовательность выполнения запроса

### 1️⃣ Получение запроса

**Файл:** `backend/routes/api.php`

**Что происходит:**
1. Запрос приходит на любой API эндпоинт
2. Роутер определяет маршрут и HTTP метод
3. Проверяется существование контроллера и метода
4. **ВАЖНО:** Все запросы проходят через единую систему авторизации

**Код:**
```php
// Определяем маршрут и метод
$route = $_GET['route'] ?? null;
$method = $_SERVER['REQUEST_METHOD'];

// Логируем запрос
Logger::info("API Request", [
    'route' => $route,
    'method' => $method,
    'timestamp' => date('c')
]);
```

### 2️⃣ Авторизация и извлечение данных

**Файл:** `backend/middleware/AuthMiddleware.php`

**Что происходит:**
1. **Извлечение Telegram данных** — из заголовков, JSON или FormData
2. **Валидация данных** — проверка обязательных полей
3. **Синхронизация пользователя** — создание/обновление через `__SyncUserDataAction`
4. **Создание сессии** — генерация уникального session_id
5. **Проверка прав доступа** — сравнение роли пользователя с требуемой

**Последовательность:**
```
AuthMiddleware::process()
├── extractTelegramData()
│   ├── extractFromHeaders()     // WebApp
│   ├── extractFromJson()        // Bot
│   └── extractFromFormData()    // Тестирование
├── validateTelegramData()
├── ensureUserExists()
│   └── __SyncUserDataAction::handle()
├── createOrUpdateSession()
└── checkAccess()
```

### 3️⃣ Маршрутизация к контроллеру

**Файл:** `backend/controllers/*.php`

**Что происходит:**
1. Создается экземпляр соответствующего контроллера
2. Контроллер получает авторизованного пользователя
3. Вызывается нужный метод контроллера
4. Контроллер подготавливает данные для Action

**Пример:**
```php
// Создаем контроллер
$controller = new UserController();

// Устанавливаем текущего пользователя
$controller->setCurrentUser($authResult['user']);

// Вызываем метод
$controller->sync();
```

### 4️⃣ Выполнение бизнес-логики

**Файл:** `backend/actions/level*/`

**Что происходит:**
1. **L1 Actions** — базовые операции с данными (CRUD)
2. **L2 Actions** — бизнес-операции (синхронизация, поиск)
3. **L3 Actions** — сложные операции с OCR и внешними API

**Последовательность выполнения Action:**
```
Action::handle($data)
├── ValidationHelper::requireFields()
├── Подготовка данных
├── Вызов L1 Actions (если нужно)
├── Выполнение основной логики
├── Сохранение результатов
└── Возврат результата
```

### 5️⃣ Работа с моделями

**Файл:** `backend/models/*.php`

**Что происходит:**
1. **Валидация данных** — проверка перед сохранением
2. **SQL запросы** — через PDO с подготовленными запросами
3. **Транзакции** — для сложных операций
4. **Возврат данных** — в структурированном виде

**Пример:**
```php
// Создание пользователя
$userData = User::create([
    'telegram_id' => $data['telegram_id'],
    'first_name_tg' => $data['first_name'],
    'last_name_tg' => $data['last_name'],
    'role_id' => $defaultRoleId
]);

// Возврат структурированных данных
return $userData->toArray();
```

### 6️⃣ Формирование ответа

**Файл:** `backend/utils/ResponseHelper.php`

**Что происходит:**
1. **Структурирование данных** — приведение к единому формату
2. **Добавление метаданных** — статус, время, пагинация
3. **Логирование** — запись результата
4. **Отправка ответа** — JSON с правильными заголовками

**Формат ответа:**
```json
{
    "success": true,
    "data": {
        "user": { ... },
        "session_id": "abc123...",
        "action": "created"
    },
    "meta": {
        "timestamp": "2024-01-15T10:30:00Z",
        "execution_time": 0.125
    }
}
```

## 🔧 Детальная схема компонентов

### Middleware слой

**Назначение:** Централизованная обработка авторизации

**Компоненты:**
- `AuthMiddleware` — основная логика авторизации
- `SessionMiddleware` — управление сессиями
- `ValidationMiddleware` — валидация входящих данных

**Порядок выполнения:**
```
1. AuthMiddleware::process()
2. SessionMiddleware::process()
3. ValidationMiddleware::process()
4. Передача управления контроллеру
```

### Контроллеры

**Назначение:** Маршрутизация запросов к Actions

**Структура:**
```
Controllers/
├── BaseController.php      // Базовый класс
├── UserController.php      // Пользователи
├── CarController.php       // Автомобили
├── BusinessCardController.php // Визитки
└── PhotoController.php     // Фотографии
```

**Методы контроллеров:**
- `sync()` — синхронизация данных
- `create()` — создание
- `update()` — обновление
- `delete()` — удаление
- `getList()` — получение списка

### Actions

**Назначение:** Бизнес-логика приложения

**Уровни:**
- **L1** — базовые операции (CRUD)
- **L2** — бизнес-операции
- **L3** — сложные операции с внешними API

**Структура:**
```
Actions/
├── level1/           # Базовые операции
├── level2/           # Бизнес-операции
├── level3/           # Сложные операции
└── helpers/          # Вспомогательные функции
```

### Модели

**Назначение:** Работа с базой данных

**Методы:**
- `create()` — создание записи
- `update()` — обновление записи
- `findById()` — поиск по ID
- `findByTelegramId()` — поиск по Telegram ID
- `toArray()` — преобразование в массив

### Утилиты

**Назначение:** Вспомогательные функции

**Компоненты:**
- `AuthHelper` — авторизация
- `SessionHelper` — сессии
- `ValidationHelper` — валидация
- `ResponseHelper` — ответы
- `Logger` — логирование

## 🔄 Потоки данных

### Поток 1: Синхронизация пользователя

```
1. WebApp/Bot → API Gateway
2. AuthMiddleware извлекает Telegram данные
3. __SyncUserDataAction проверяет/создает пользователя
4. SessionHelper создает сессию
5. Возвращается результат с session_id
```

### Поток 2: Работа с автомобилями

```
1. Клиент → API Gateway (с session_id)
2. AuthMiddleware проверяет сессию
3. CarController получает пользователя
4. __SearchCarAction выполняет поиск
5. Car::findByPlateNumber() ищет в БД
6. Возвращается результат
```

### Поток 3: OCR операции

```
1. Клиент → API Gateway (с фото)
2. AuthMiddleware авторизует пользователя
3. ___CheckCarInClubAction обрабатывает запрос
4. RecognizeCarNumberFromPhotoAction выполняет OCR
5. __SearchCarAction создает/находит автомобиль
6. Возвращается результат
```

## 🛡️ Безопасность на каждом уровне

### Уровень 1: Валидация входных данных
- Проверка типов данных
- Валидация обязательных полей
- Санитизация входных данных

### Уровень 2: Авторизация
- Проверка сессии
- Валидация прав доступа
- Логирование попыток доступа

### Уровень 3: Бизнес-логика
- Проверка бизнес-правил
- Валидация транзакций
- Обработка ошибок

### Уровень 4: База данных
- Подготовленные запросы
- Транзакции для сложных операций
- Проверка ограничений

## 📊 Мониторинг и логирование

### Что логируется на каждом уровне

**API Gateway:**
- Входящие запросы
- Маршрутизация
- Время отклика

**AuthMiddleware:**
- Попытки авторизации
- Создание сессий
- Ошибки валидации

**Controllers:**
- Вызовы методов
- Передача данных к Actions
- Ошибки контроллеров

**Actions:**
- Выполнение бизнес-логики
- Вызовы внешних API
- Результаты операций

**Models:**
- SQL запросы
- Ошибки БД
- Время выполнения запросов

## 🎯 Преимущества архитектуры

1. **Модульность** — каждый компонент отвечает за свою область
2. **Переиспользование** — общие функции вынесены в утилиты
3. **Безопасность** — многоуровневая защита
4. **Масштабируемость** — легко добавлять новые функции
5. **Отладка** — подробное логирование на всех уровнях
6. **Производительность** — оптимизация на каждом уровне

Эта архитектура обеспечивает надежную, безопасную и масштабируемую систему, где каждый компонент имеет четко определенную ответственность и взаимодействует с другими через стандартизированные интерфейсы.
