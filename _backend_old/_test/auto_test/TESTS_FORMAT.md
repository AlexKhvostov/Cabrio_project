# Формат тестов для автотестов CabrioRide

Документ описывает структуру файла `endpoints_test_config.json` и правила подготовки тестов для автоматической проверки API.

---

## Общие принципы
- Каждый эндпоинт описывается отдельным объектом с полем `url` и массивом `tests`.
- Для каждого эндпоинта рекомендуется использовать **8 стандартных тестов** (см. ниже).
- Все тесты должны быть максимально читаемы и оформлены с отступами.
- Все значения, которые могут меняться (например, id, номера, имена), должны быть валидными для тестовой базы.
- Не используйте комментарии внутри JSON (это невалидно для парсера).

---

## Структура файла endpoints_test_config.json

```json
[
    {
        "url": "/api/endpoint/path",
        "tests": [
            {
                "type": "1. Успех 1",
                "request": { "auth": { "user_id": 1, "role": "member" }, "data": { /* ... */ } },
                "expect": { "success": true, "result.some_field": "value" }
            },
            // ... остальные тесты
        ]
    },
    // ... другие эндпоинты
]
```

### Описание полей
- `url` — путь к эндпоинту (строка, обязательно, должен совпадать с endpoints_list.json)
- `tests` — массив тестов для этого эндпоинта
    - `type` — краткое описание теста (строка, например: "1. Успех 1", "3. Ошибка: дубликат")
    - `request` — тело запроса (объект, структура зависит от эндпоинта)
    - `expect` — ожидаемый результат (объект, минимум: `{ "success": true/false }`, можно указывать дополнительные поля для проверки)

---

## Рекомендуемый набор тестов для каждого эндпоинта

1. **Успех 1** — валидные данные, ожидается успех
2. **Успех 2** — альтернативные валидные данные, ожидается успех
3. **Успех с ошибкой** — например, дубликат, несуществующий id, ожидается ошибка (422/404)
4. **Ошибка: неправильный запрос** — неверная структура запроса (например, лишние/неверные поля), ожидается ошибка 400
5. **Ошибка: ограничение доступа** — недостаточно прав (роль ниже минимальной), ожидается ошибка 403
6. **Ошибка: невалидные данные** — неверный тип/формат данных, ожидается ошибка 400
7. **Ошибка: нет обязательного поля** — отсутствует обязательное поле, ожидается ошибка 400
8. **Ошибка: пустой JSON** — полностью пустой запрос, ожидается ошибка 400

> Для некоторых эндпоинтов отдельные тесты могут быть неактуальны (например, ограничение доступа для публичных методов) — в этом случае тест можно опустить, но лучше явно указать причину.

## Пример тестов для эндпоинта

```json
{
    "url": "/api/users/add",
    "tests": [
        {
            "type": "1. Успех 1",
            "request": { "auth": {}, "data": { "telegram_id": 123456, "username": "testuser", "first_name": "Test", "last_name": "User" } },
            "expect": { "success": true }
        },
        {
            "type": "2. Успех 2",
            "request": { "auth": {}, "data": { "telegram_id": 654321, "username": "anotheruser", "first_name": "Ivan", "last_name": "Ivanov" } },
            "expect": { "success": true }
        },
        {
            "type": "3. Ошибка: дубликат",
            "request": { "auth": {}, "data": { "telegram_id": 123456, "username": "testuser", "first_name": "Test", "last_name": "User" } },
            "expect": { "success": false, "error.code": 422 }
        },
        {
            "type": "4. Ошибка: неправильный запрос",
            "request": { "foo": "bar" },
            "expect": { "success": false, "error.code": 400 }
        },
        {
            "type": "5. Ошибка: ограничение доступа",
            "request": { "auth": { "user_id": 1, "role": "guest" }, "data": { "telegram_id": 123456, "username": "testuser", "first_name": "Test", "last_name": "User" } },
            "expect": { "success": false, "error.code": 403 }
        },
        {
            "type": "6. Ошибка: невалидные данные",
            "request": { "auth": {}, "data": { "telegram_id": "notanumber", "username": "", "first_name": "", "last_name": "" } },
            "expect": { "success": false, "error.code": 400 }
        },
        {
            "type": "7. Ошибка: нет обязательного поля",
            "request": { "auth": {}, "data": {} },
            "expect": { "success": false, "error.code": 400 }
        },
        {
            "type": "8. Ошибка: пустой JSON",
            "request": {},
            "expect": { "success": false, "error.code": 400 }
        }
    ]
}
```

---

## Рекомендации
- Всегда используйте валидный JSON (без комментариев, с правильными кавычками и запятыми).
- Проверяйте, что url в тестах совпадает с url в endpoints_list.json.
- Для OCR-тестов используйте реальные имена файлов из папки __test_ jpg.
- Если структура ответа сложная — можно проверять вложенные поля через точку (например, "result.user_id": 1).
- Если тест неактуален для эндпоинта — оставьте пустой объект или пояснение в type.
