# 🔐 Обзор системы авторизации

> **Назначение:** Система безопасности и авторизации бэкенда CabrioRide  
> **Версия:** 1.0.0  
> **Последнее обновление:** 2024-01-01

---

## 🎯 **Принципы авторизации**

### **1. Централизованная авторизация**
- Единая точка авторизации через `AuthMiddleware`
- Все запросы проходят через один middleware
- Централизованная конфигурация прав доступа

### **2. Ролевая модель доступа**
- Права определяются только по роли пользователя
- Роли: `external`, `guest`, `new`, `registered`, `member`, `moderator`, `admin`
- Централизованная конфигурация в `config/sectionGroups.php`

### **3. Множественные типы авторизации**
- **Telegram WebApp** — через Telegram данные
- **Telegram Bot** — через системные токены
- **SYSTEM_TOKEN** — для внутренних сервисов
- **DEV-мод** — для разработки и тестирования

### **4. Безопасность данных**
- Валидация Telegram hash
- Проверка подписи данных
- Безопасные токены сессий
- Аудит всех операций

---

## 🏗️ **Архитектура авторизации**

### **Основные компоненты**

#### **1. AuthMiddleware**
- **Назначение:** Централизованная обработка авторизации
- **Расположение:** `middleware/AuthMiddleware.php`
- **Функции:**
  - Извлечение Telegram данных
  - Валидация данных
  - Синхронизация пользователя
  - Создание/обновление сессии
  - Установка глобального контекста

#### **2. AuthHelper**
- **Назначение:** Утилиты для авторизации
- **Расположение:** `utils/AuthHelper.php`
- **Функции:**
  - Извлечение Telegram данных из различных источников
  - Валидация Telegram данных
  - Проверка подписи Telegram
  - Работа с JWT токенами (legacy)

#### **3. SessionHelper**
- **Назначение:** Управление сессиями
- **Расположение:** `utils/SessionHelper.php`
- **Функции:**
  - Создание и обновление сессий
  - Валидация активных сессий
  - Удаление сессий
  - Очистка устаревших сессий

#### **4. AppContext**
- **Назначение:** Глобальный контекст приложения
- **Расположение:** `utils/AppContext.php`
- **Функции:**
  - Хранение данных текущего пользователя
  - Управление сессией
  - Telegram данные
  - Метаданные запроса

---

## 🔄 **Поток авторизации**

### **Стандартный поток**
```
HTTP Request → AuthMiddleware → AuthHelper → SessionHelper → AppContext
                ↓              ↓              ↓
           Telegram Data   Validation   Session Management
                ↓              ↓              ↓
           User Sync    Hash Check    Global Context
```

### **Детальный процесс**

1. **Извлечение данных** — получение Telegram данных из запроса
2. **Валидация** — проверка корректности данных и подписи
3. **Синхронизация пользователя** — создание/обновление пользователя
4. **Управление сессией** — создание или обновление сессии
5. **Установка контекста** — настройка глобального контекста
6. **Проверка прав** — проверка доступа к запрашиваемому ресурсу

## 🔐 **Типы авторизации**

### **1. Telegram WebApp**
- **Источник данных:** Заголовки HTTP
- **Валидация:** Проверка подписи Telegram
- **Использование:** WebApp приложения
- **Пример:**
```http
X-Telegram-User-Id: 123456789
X-Telegram-First-Name: Иван
X-Telegram-Last-Name: Иванов
X-Telegram-Username: ivan
X-Telegram-Hash: abc123...
```

### **2. Telegram Bot**
- **Источник данных:** JSON тело запроса
- **Валидация:** Проверка структуры данных
- **Использование:** Telegram бот
- **Пример:**
```json
{
  "message": {
    "from": {
      "id": 123456789,
      "first_name": "Иван",
      "last_name": "Иванов",
      "username": "ivan"
    }
  }
}
```

### **3. SYSTEM_TOKEN**
- **Источник данных:** Bearer токен в заголовке
- **Валидация:** Сравнение с системным токеном
- **Использование:** Внутренние сервисы
- **Пример:**
```http
Authorization: Bearer SYSTEM_TOKEN_VALUE
```

### **4. DEV-мод**
- **Активация:** Переменная окружения `DEV_AUTH=true`
- **Использование:** Разработка и тестирование
- **Конфигурация:**
  - `DEV_USER_ID` — ID пользователя для тестирования
  - `DEV_ROLE` — роль для подмены

## 🛡️ **Безопасность**

### **Валидация Telegram данных**
- Проверка обязательных полей
- Валидация типов данных
- Проверка длины строк
- Валидация подписи Telegram

### **Проверка подписи**
```php
// Алгоритм проверки подписи Telegram
private static function isHashValid(array $data): bool
{
    if (empty($data['hash'])) {
        return false;
    }
    
    $recvHash = $data['hash'];
    unset($data['hash']);
    
    ksort($data, SORT_STRING);
    $pairs = [];
    foreach ($data as $k => $v) {
        $pairs[] = $k . '=' . $v;
    }
    $dataCheckString = implode("\n", $pairs);
    
    $botToken = getenv('BOT_TOKEN');
    $secretKey = hash('sha256', $botToken, true);
    $calculatedHash = hash_hmac('sha256', $dataCheckString, $secretKey);
    
    return hash_equals($calculatedHash, $recvHash);
}
```

### **Защита сессий**
- Уникальные токены сессий
- Ограниченное время жизни
- Автоматическая очистка устаревших сессий
- Безопасное хранение в базе данных

## 👥 **Ролевая модель**

### **Роли пользователей**
1. **external** (ID: 1) — внешние пользователи
2. **guest** (ID: 2) — гости
3. **new** (ID: 3) — новые пользователи
4. **registered** (ID: 4) — зарегистрированные
5. **member** (ID: 5) — участники клуба
6. **moderator** (ID: 6) — модераторы
7. **admin** (ID: 7) — администраторы

### **Иерархия ролей**
```
admin > moderator > member > registered > new > guest > external
```

### **Централизованная конфигурация**
- Все права доступа определяются в `config/sectionGroups.php`
- Функции API привязаны к минимальным ролям
- Автоматическая проверка прав через `requireAccess()`

## 🔧 **DEV-мод для разработки**

### **Активация**
```bash
# В .env файле
DEV_AUTH=true
DEV_USER_ID=999
DEV_ROLE=admin
```

### **Функции**
- **Байпас авторизации** — пропуск Telegram авторизации
- **Подмена роли** — установка любой роли для тестирования
- **Фиктивный пользователь** — использование тестового ID

### **Безопасность**
- Работает только вне production
- Подробное логирование всех DEV-операций
- Не влияет на продакшн-среду

## 🚨 **Обработка ошибок**

### **Типы ошибок**
- `NO_TELEGRAM_DATA` — отсутствуют данные Telegram
- `TELEGRAM_VALIDATION_ERROR` — ошибка валидации
- `INVALID_HASH` — недействительная подпись
- `USER_SYNC_ERROR` — ошибка синхронизации пользователя
- `SESSION_CREATION_ERROR` — ошибка создания сессии
- `FORBIDDEN` — недостаточно прав

### **HTTP статусы**
- **401 Unauthorized** — ошибки авторизации
- **403 Forbidden** — недостаточно прав
- **500 Internal Server Error** — внутренние ошибки
